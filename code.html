AI 网站自动收录与分类导航 — 完整实施手册

目标：搭建一个部署在 GitHub Pages 上的 AI 站点导航，每日通过 GitHub Actions 自动抓取新站、自动分类、自动更新静态数据，无需人工维护。月成本 < ¥10。

1. 整体架构

┌─ GitHub Actions (cron 每日触发)
│    ↓
├─ checkout 仓库
│    ↓
├─ 运行 Node 爬虫 (axios + cheerio)
│    ├─ models.dev API
│    ├─ awesome-* 清单
│    ├─ HN Algolia API
│    ├─ Product Hunt RSS
│    └─ 目录站 HTML 抓取
│    ↓
├─ 去重 → 规则分类 → LLM 兜底 → 打分
│    ↓
├─ 生成 data/data.json
│    ↓
├─ git commit + push
│    ↓
└─ GitHub Pages 自动重新部署
        ↓
   浏览器 fetch('./data/data.json') 渲染

核心原则：

  • Pages 只负责静态托管，"更新"的本质是让 Actions 把新 data.json commit 进仓库
  • 浏览器 JS 不能爬虫（同源策略），真正干活的是 Actions 云端容器里的 Node.js
  • 90% 站点用域名关键词即可分类，仅冷门站走 LLM 兜底，节省 token 开销

4. 分类逻辑实现

三级分类：域名白名单 → 关键词规则 → LLM 兜底

// scripts/classifier.mjs
const RULES = [
  { cat: 'coding-agent',    any: ['claude-code', 'cli', 'terminal', 'coding-agent', 'code-assistant', 'opencode', 'commandcode'] },
  { cat: 'token-gateway',   any: ['api-key', 'token', 'pricing', 'billing', 'gateway', 'inference', 'credits'] },
  { cat: 'llm-provider',    any: ['llm', 'gpt', 'claude', 'deepseek', 'qwen', 'kimi', 'minimax'] },
  { cat: 'free-api',        any: ['free-tier', 'free-llm', 'free-api'] },
  { cat: 'ai-directory',    any: ['directory', 'tools-list', 'awesome-', 'navigate', 'catalog'] },
  { cat: 'agent-framework', any: ['agent', 'mcp', 'framework', 'orchestration'] },
];

export function ruleClassify(item) {
  const text = `${item.url} ${item.title} ${item.description}`.toLowerCase();
  const hits = RULES.filter(r => r.any.some(kw => text.includes(kw)));
  return hits.length ? hits[0].cat : null;
}

export async function llmClassify(item, CATEGORIES) {
  const prompt = `请把下面这个网站归到唯一一个分类里，只输出分类 ID。
分类选项：${CATEGORIES.map(c => `${c.id} (${c.name})`).join(', ')}
网站：${item.url}
标题：${item.title}
描述：${item.description}
只输出分类 ID，不要解释。`;

  const res = await fetch('https://api.deepseek.com/v1/chat/completions', {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${process.env.DEEPSEEK_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model: 'deepseek-chat',
      messages: [{ role: 'user', content: prompt }],
      max_tokens: 20,
    }),
  });
  const data = await res.json();
  return data.choices[0].message.content.trim();
}

export async function classify(item, CATEGORIES) {
  return ruleClassify(item) ?? await llmClassify(item, CATEGORIES);
}

成本参考：DeepSeek-Chat 单次分类调用 < 1 分钱，每日兜底消耗 < 1 元。

必须做 LLM 结果缓存：以 URL 哈希为 key 存到本地 JSON，避免每日重复调用。

5. 爬虫脚本

5.1 基础爬虫模板

// scripts/crawler.mjs
import axios from 'axios';
import * as cheerio from 'cheerio';
import { writeFile } from 'node:fs/promises';

const SITES = [
  'https://opencode.ai',
  'https://openrouter.ai',
  'https://deepseek.com',
];

const results = [];
for (const url of SITES) {
  try {
    const { data: html } = await axios.get(url, {
      headers: { 'User-Agent': 'Mozilla/5.0 (compatible; AISitesBot/1.0)' },
      timeout: 10000,
    });
    const $ = cheerio.load(html);
    const title = $('title').text().trim();
    const description = $('meta[name="description"]').attr('content') || '';
    results.push({ url, title, description, fetchedAt: new Date().toISOString() });
    await new Promise(r => setTimeout(r, 1000)); // 礼貌性延迟
  } catch (e) {
    console.warn(`跳过 ${url}: ${e.message}`);
    // 单源失败不影响整体，继续下一个
  }
}

await writeFile('./data/raw.json', JSON.stringify(results, null, 2));

5.3 去重规则

function normalizeUrl(u) {
  const url = new URL(u);
  url.hostname = url.hostname.replace(/^www\./, '');
  url.search = '';      // 去掉 query
  url.hash = '';        // 去掉 hash
  let s = url.toString();
  if (s.endsWith('/')) s = s.slice(0, -1);
  return s;
}

同一站点被多个源收录时合并，出现次数累加为 score 的一部分。

6. GitHub Actions 工作流

保存为 .github/workflows/crawl.yml：

name: Daily AI Sites Crawl

on:
  schedule:
    - cron: '23 3 * * *'   # 每天 UTC 3:23（北京时间 11:23），避开整点高峰
  workflow_dispatch:        # 允许手动触发调试

permissions:
  contents: write           # 必须，否则 git push 会 403

jobs:
  crawl:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'

      - run: npm install

      - run: node scripts/main.mjs
        env:
          DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_API_KEY }}

      - name: Commit & Push
        run: |
          git config user.name  "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add data/
          git diff --cached --quiet || git commit -m "chore: refresh AI sites $(date -u +%F)"
          git push

Secrets 配置：仓库 Settings → Secrets and variables → Actions → New repository secret，添加 DEEPSEEK_API_KEY。

7. 前端展示

7.1 index.html 核心逻辑

<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="UTF-8">
  <title>AI Sites Navigator</title>
  <style>
    body { font-family: -apple-system, sans-serif; max-width: 1200px; margin: 0 auto; padding: 2rem; }
    .card { border: 1px solid #e2e2e2; border-radius: 8px; padding: 1rem; margin: .5rem; display: inline-block; width: 300px; vertical-align: top; }
    .tag { background: #eef; padding: 2px 8px; border-radius: 4px; font-size: .8em; }
    .offline { opacity: .5; }
  </style>
</head>
<body>
  <h1>AI 站点导航</h1>
  <input id="search" placeholder="搜索..." oninput="render()" style="width:300px;padding:8px;">
  <div id="list"></div>

  <script>
    let sites = [];
    fetch('./data/data.json').then(r => r.json()).then(d => { sites = d; render(); });

    function render() {
      const q = document.getElementById('search').value.toLowerCase();
      const filtered = sites.filter(s =>
        !q || s.title?.toLowerCase().includes(q) || s.description?.toLowerCase().includes(q)
      );
      const grouped = {};
      filtered.forEach(s => {
        (grouped[s.category] ||= []).push(s);
      });

      document.getElementById('list').innerHTML = Object.entries(grouped).map(([cat, items]) => `
        <h2>${cat}</h2>
        ${items.map(s => `
          <div class="card ${s.status === 'offline' ? 'offline' : ''}">
            <a href="${s.url}" target="_blank">${s.title || s.url}</a>
            <p>${s.description || ''}</p>
            <span class="tag">${s.category}</span>
            <span style="float:right;font-size:.8em;color:#999">${s.lastSeenAt?.slice(0,10)}</span>
          </div>
        `).join('')}
      `).join('');
    }
  </script>
</body>
</html>

7.2 推荐功能

  • 搜索框：按标题/描述过滤
  • Trending 区：显示最近 7 天新增或 score 上升的站点
  • 分类筛选 tab
  • 站点截图占位（可选，用 api.microlink.io/?url=xxx&screenshot 之类服务）
  • "信息较旧"标注：lastSeenAt 距今超过 90 天的显示灰色提示

8. 避坑清单

#坑规避方式
1cron 整点触发延迟甚至丢失写成 23 3 * * * 这类"零散分钟"
260 天无仓库活动定时任务被静默停用每日 commit 天然算活动；若源全挂无 commit，偶尔手动跑一次
3GITHUB_TOKEN 推 commit 不触发其他 workflowPages 用 "Deploy from a branch" 模式不受影响；如需链式触发用 workflow_call
4push 报 403workflow 里加 permissions: contents: write
5单个源挂掉导致整个 job 失败每个 source 用 try/catch 包裹，失败记日志继续下一个
6LLM 分类重复调用浪费 token按 URL 哈希做本地缓存
7爬目录站被反爬加 User-Agent + 每请求 sleep 1 秒 + 重试上限；改抓 sitemap.xml
8同一站点被多源重复收录URL 规范化后合并，出现次数累加为热度权重
9站点下线后还留在页面上每日 ping 所有 URL，连续 7 天 404 标 offline，不要直接删
10版权风险只存元数据（标题+链接+描述），不搬运正文；遵守 robots.txt
11私有仓库 Actions 超额公共仓库免费无上限；私有仓库月 2000 分钟足够每日 1 次

9. 快速上手步骤

Day 1：跑通基础链路

  1. 创建 GitHub 仓库（Public），本地 git clone
  2. 建目录结构： 
    ├── .github/workflows/crawl.yml
├── scripts/
│   ├── crawler.mjs
│   ├── classifier.mjs
│   └── main.mjs
├── data/
├── index.html
└── package.json
  3. package.json 依赖： 
    {
  "type": "module",
  "dependencies": {
    "axios": "^1.x",
    "cheerio": "^1.x"
  }
}
  4. 在 workflow 里先注释掉 schedule，保留 workflow_dispatch
  5. 手动触发 Actions → 观察是否成功 commit → 看 Pages 是否部署

Day 2：接入信息源

  • 按第 2 节表格，每接一个源就跑一次，观察 data/raw.json 输出是否符合预期
  • 先接 models.dev（最容易）→ HN Algolia → awesome 清单 → RSS → HTML 目录

Day 3：启用定时

  • 确认手动跑稳定后，打开 schedule.cron
  • 观察一周，如有延迟属正常（官方说明高峰期可能延迟）

Day 4+：迭代

  • 加搜索/筛选/截图
  • 加 Trending / 评分
  • 加更多源

附录 C：法律与礼仪提醒

  • 优先用官方 API / RSS，不要硬爬 HTML
  • 遵守目标站点 robots.txt
  • 控制请求频率（≥1 秒/次），不要把小站打挂
  • 不爬明确禁止自动化的站点
  • 公共仓库代码所有人可见，注意合规留痕
  • 只存元数据，避免版权争议
